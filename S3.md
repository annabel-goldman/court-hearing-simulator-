# S3 Asset Hosting Setup (Frontend GLB + Media)

This project can load heavy frontend assets from S3/CloudFront when enabled with:

- `VITE_USE_S3_ASSETS=true`
- `VITE_ASSET_BASE_URL`

Code paths using this:

- `/Users/Annie/Desktop/  /Court Simulator/frontend/src/3d-rendering/scenePresets.ts`
- `/Users/Annie/Desktop/  /Court Simulator/frontend/src/components/LandingAgreementAvatar.tsx`
- `/Users/Annie/Desktop/  /Court Simulator/frontend/src/pages/Home.tsx`

## 1. Create the S3 bucket

1. AWS Console -> S3 -> Create bucket.
2. Use a globally unique bucket name, for example: `court-simulator-assets-annie`.
3. Region: pick one near your users.
4. Keep **Block all public access** ON if you will use CloudFront + OAC (recommended).

## 2. Put CloudFront in front (recommended)

1. AWS Console -> CloudFront -> Create distribution.
2. Origin domain: your S3 bucket.
3. If prompted, create/use Origin Access Control (OAC).
4. Viewer protocol policy: `Redirect HTTP to HTTPS`.
5. Default root object can be left blank (this is asset hosting, not a site root).
6. After deploy, copy your distribution domain, e.g. `https://d123abcde.cloudfront.net`.

## 3. Upload assets with the exact path layout expected by the app

From repo root (`/Users/Annie/Desktop/  /Court Simulator`):

```bash
BUCKET="court-simulator-assets-annie"
PREFIX="court-simulator-assets"

# Courtroom GLBs (all judge/lawyer/furniture animation files)
aws s3 sync "frontend/src/3d-rendering/glb" "s3://$BUCKET/$PREFIX/3d-rendering/glb" \
  --exclude "*" --include "*.glb"

# Beam GLB (stored inside the same local glb folder)
aws s3 cp "frontend/src/3d-rendering/glb/beam.glb" "s3://$BUCKET/$PREFIX/3d-rendering/glb/beam.glb"

# Landing assets used by Home page
aws s3 cp "frontend/public/Background.jpg" "s3://$BUCKET/$PREFIX/Background.jpg"
aws s3 cp "frontend/public/bench-logo.svg" "s3://$BUCKET/$PREFIX/bench-logo.svg"
```

## 4. Set `VITE_USE_S3_ASSETS` + `VITE_ASSET_BASE_URL`

Set this to your CloudFront domain + prefix, with trailing slash:

```text
https://d123abcde.cloudfront.net/court-simulator-assets/
```

### GitHub Actions (production)

Add repo secret:

- `VITE_USE_S3_ASSETS` = `true`
- `VITE_ASSET_BASE_URL` = `https://d123abcde.cloudfront.net/court-simulator-assets/`

The workflow already passes this into the frontend build:

- `/Users/Annie/Desktop/  /Court Simulator/.github/workflows/deploy.yml`

### Local dev

Add to root `.env`:

```env
VITE_USE_S3_ASSETS=true
VITE_ASSET_BASE_URL=https://d123abcde.cloudfront.net/court-simulator-assets/
```

Then run frontend as usual.

If `VITE_USE_S3_ASSETS` is `false` or unset, the app falls back to local bundled GLB assets.

## 5. CORS (required)

If your frontend origin is GitHub Pages, allow it in S3 bucket CORS.

S3 -> Bucket -> Permissions -> CORS:

```json
[
  {
    "AllowedHeaders": ["*"],
    "AllowedMethods": ["GET", "HEAD"],
    "AllowedOrigins": ["https://YOUR_GITHUB_USERNAME.github.io"],
    "ExposeHeaders": []
  }
]
```

If you use multiple frontend origins, add each origin.

## 6. Verify

After deploy, open DevTools Network and confirm GLBs load from CloudFront:

- `.../court-simulator-assets/3d-rendering/glb/...`
- `.../court-simulator-assets/3d-rendering/glb/beam.glb`

You should no longer see Vite-hashed GLB files served from your GitHub Pages bundle.

## 7. Optional cache optimization

For immutable binary assets, use long cache headers:

- `Cache-Control: public, max-age=31536000, immutable`

Set via `aws s3 cp --metadata-directive REPLACE --cache-control ...` or CloudFront behavior/policy.
